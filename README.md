# Lobby Bot

Discord-бот для сообщества многопользовательской игры жанра social deduction: запуск выделенных
игровых серверов из Discord, ELO-рейтинг с сезонами, статистика матчей, мониторинг лобби и оповещения
о стримах. Работает в продакшене на нескольких Discord-серверах.

**Стек:** Python 3.13, discord.py 2.6, MongoDB (асинхронный `pymongo.AsyncMongoClient`), paramiko (SSH/SFTP),
matplotlib, pyvis/networkx, Docker. Качество: pytest, ruff, pre-commit, GitHub Actions.

## Что умеет

| Фича | Что делает |
|---|---|
| `servers` | Панель игровых серверов: запуск с выбором карты, модов и модификаторов, резерв, остановка, учёт хоста. Команда запуска собирается из правил и уходит на сервер по SSH |
| `console` | Консоль администратора матча: телепорт по координатам, сохранённые и общие точки, выдача предметов |
| `elo` | Расчёт ELO по очереди сыгранных матчей: калибровка, серии побед, штрафы, твинки, ручные правки и откат матча модератором |
| `seasons` | Сезоны рейтинга: текущий сезон — единственный источник правды для всех фич, сброс командой |
| `leaderboard` | Таблицы лидеров в каналах, карточка игрока с графиком ELO, история матчей, статистика пар |
| `match_stats` | Импорт файлов статистики матчей (CSV/JSON) с игровых серверов, публикация карты матча на сайт |
| `match_results` | Итоги матча в Discord: изменения ELO, урон по игрокам, репорт на игрока из итогов |
| `reports` | Репорты на игроков с логом для модераторов |
| `lobbies` | Мониторинг публичных лобби через API игровой платформы |
| `graphs` | Граф связей игроков (pyvis) и ежедневные графики |
| `twitch`, `roles`, `players`, `dm_log`, `tournament` | Оповещения о стримах, роли по реакциям, ники игроков, лог личных сообщений, турнирный режим |

## Архитектура

```
lobby_bot/
  app.py            LobbyBot: создаёт Database, загружает фичи (EXTENSIONS), синхронизирует slash-команды
  settings.py       все настройки из .env (pydantic-settings), секреты как SecretStr
  db.py             Database: AsyncMongoClient и коллекции
  features/<имя>/   фича = Cog: cog.py (Discord), service.py (правила), repo.py (MongoDB), api.py (внешний API)
  shared/           общее: права, загрузка на сайт
```

- **Фича = расширение discord.py.** Подключается строкой в `EXTENSIONS`, выключается её удалением или
  флагом `*_ENABLED`. Фичи общаются только через `service` друг друга или через события `bot.dispatch`.
- **Зависимости явно.** `Database` создаётся в `setup_hook` и закрывается в `close`. Фича в `setup(bot)`
  собирает свои репозитории из `bot.db` и передаёт их в Cog через конструктор. Глобальных подключений
  и запросов к базе при импорте нет.
- **Асинхронно до конца.** MongoDB через асинхронный клиент; блокирующее (SSH, рендер графиков, чтение файлов)
  уходит в `asyncio.to_thread`. Фоновые задачи (`tasks.loop`) не падают навсегда от одной ошибки.
- **Persistent-кнопки.** Панели и кнопки под старыми сообщениями работают после перезапуска
  (`add_view`, `DynamicItem`).

Подробно: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Запуск

```bash
cp .env.example .env        # заполнить: токен Discord, MONGO_URL, ID каналов и ролей
docker compose up -d --build
```

Локально без Docker: `pip install -r requirements.txt`, затем `python -m lobby_bot`.
Развёртывание на сервере и выкатка по `git push`: [`docs/SERVER.md`](docs/SERVER.md), Docker:
[`docs/DOCKER.md`](docs/DOCKER.md).

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
ruff check . && ruff format --check .
```

- Реальные Discord, MongoDB, SSH и `.env` не нужны: MongoDB подменён mongomock с асинхронной обёрткой,
  SSH/SFTP и HTTP — фейками на уровне клиента, настройки заполняются из `.env.example`.
- Поведение, перенесённое при рефакторинге старого кода, зафиксировано snapshot-эталонами (ответы
  в Discord, SSH-команды, всё, что записано в базу). Смоук-тест старта проверяет набор фич, задач
  и slash-команд.
- Предупреждения считаются ошибками, тесты идут в часовом поясе прода, известный баг закреплён
  `xfail(strict=True)`.

# Новая фича в lobby_discord_bot

Процедура для новой фичи в `lobby_bot/features/<имя>/`. Общие правила проекта (секреты, права, сезон, логи) в CLAUDE.md, здесь только порядок шагов. Образец маленькой фичи с задачей и флагом: `lobby_bot/features/tournament/`.

## 0. Перед началом
- Уточни у пользователя: имя фичи (snake_case), команды (slash или `!`), нужны ли фоновые задачи, коллекции MongoDB, внешний API, выключаемая ли фича.
- Каждый коммит в `main` сразу выкатывается в прод. Работай в отдельной ветке, если пользователь не сказал иначе.

## 1. Папка и файлы
```
lobby_bot/features/<имя>/
  __init__.py   docstring: что делает фича, как подключается (lobby_bot.features.<имя>.cog)
  cog.py        Discord: команды, кнопки, задачи, embed'ы; async def setup(bot)
  service.py    логика без discord (только если она есть)
  api.py        внешний API (только если есть)
  repo.py       MongoDB (только если есть свои коллекции)
```
- Лишние файлы не создавать. `views.py` отдельно только когда `cog.py` больше ~800 строк.
- Cog не импортирует `bot` из app.py, использует `self.bot`.
- Зависимости (repo, ID каналов) собираются в `setup()` и передаются в конструктор Cog: так Cog тестируется с фейками.
- Фичи общаются только через `service` другой фичи или события `self.bot.dispatch("имя", данные)` + `@commands.Cog.listener() on_имя`. Новое событие описать в `docs/ARCHITECTURE.md`.
- Общий код нескольких фич в `lobby_bot/shared/`.

## 2. MongoDB
- Новая коллекция объявляется в классе `Database` (`lobby_bot/db.py`), не в фиче.
- `repo.py`: класс `<Имя>Repo`, асинхронные коллекции (`AsyncCollection`) в конструкторе, методы `async`.
  Repo собирается в `setup()` из `bot.db.<коллекция>` и передаётся в конструктор Cog.
- Индексы: метод `ensure_indexes()` в repo, вызывать один раз за запуск в первой итерации задачи (флаг `_indexes_ready`), не в `cog_load`: недоступная база не должна мешать старту.
- Ввод пользователя в `$regex` только через `re.escape`.
- Сезон только через `await current_season(seasons)` из `lobby_bot/features/seasons/service.py` (SeasonsRepo
  собирается в `setup()` через `seasons_repo(bot.db)`), параметры `season=None`.

## 3. Настройки
- Каждый новый ключ: поле в `Settings` (`lobby_bot/settings.py`, имя = переменная в нижнем регистре, с типом) и строка в `.env.example`. Без этого тесты не получат фейковое значение.
- Секреты типа `SecretStr`, необязательные через `secret_value()`.
- Литералы ID каналов, ролей, адресов в коде не писать.
- Выключаемая фича: `<ИМЯ>_ENABLED: bool = False` в `Settings`, проверка в `cog_load` перед стартом задач. Не комментировать код и не убирать из `EXTENSIONS` ради выключения.
- Сказать пользователю, какие ключи добавить в боевой `.env`. Сам `.env` не читать и не менять.

## 4. Команды и права
- Все `!`-команды и `[Мод]`-команды только для модераторов: `cog_check = moderator_check` для всего Cog или `@moderator_only()` для одной команды (`lobby_bot/shared/permissions.py`).
- Команда без проверки прав только осознанно, сказать об этом пользователю.
- Кнопки и меню, которые должны жить после рестарта: `bot.add_view` / `bot.add_dynamic_items` в `setup()` фичи.

## 5. Фоновые задачи
- `@tasks.loop` в Cog: `start()` в `cog_load`, `cancel()` в `cog_unload`, `before_loop` ждёт `self.bot.wait_until_ready()`.
- Тело задачи целиком в `try/except Exception` с `logger.exception`: необработанное исключение навсегда останавливает задачу.
- Блокирующее (paramiko, тяжёлые расчёты) через `asyncio.to_thread`. MongoDB асинхронный, его не оборачивать.
- Первая итерация выполняется сразу при `start()`, не вызывать её вручную.

## 6. Регистрация
- Строка `"lobby_bot.features.<имя>.cog"` в `EXTENSIONS` (`lobby_bot/app.py`).

## 7. Тесты
- `tests/features/<имя>/__init__.py` (пустой), `test_*.py`, фейки фичи в её `conftest.py`. Общие фейки: `tests/fakes.py`.
- Тестировать: чистые функции service, repo на mongomock (`wrap(mongomock.MongoClient().db.<коллекция>)` из `tests/async_mongo.py`), Cog с фейковым ботом и repo (`SimpleNamespace`), задачу через `await cog.<task>.coro(cog)`, проверку прав.
- `tests/test_startup.py` обязательно обновить:
  - `test_cogs_and_persistent_items_registered`: имя нового Cog, persistent view и dynamic items;
  - `test_background_tasks_started`: новые задачи (выключенные флагом по умолчанию не стартуют);
  - `tests/commands_snapshot.txt`: новые команды (slash без префикса, `!`-команды с `!`), список отсортирован. Правильный список печатается в сообщении упавшего теста.
- Прогнать весь `pytest` из корня, не только тесты фичи.

## 8. Окончания строк
- Файлы проекта в CRLF. Новые `.py` писать с CRLF, существующие не перекодировать (при правке скриптом: `open(p, newline='')`).
- `*.sh`, `.githooks/*`, `deploy/post-receive` только LF.
- Перед сдачей проверить `git diff --stat`: если изменились все строки файла, сломаны окончания строк.

## 9. Документация
- `docs/ARCHITECTURE.md`, раздел «Фичи»: пункт о фиче (что делает, команды, задачи, коллекции).
- Там же «Фоновые задачи» (новые задачи с интервалом), «События между фичами», «Persistent-кнопки и меню».
- Docstring в `lobby_bot/features/<имя>/__init__.py`: одна строка, что делает фича.
- `CLAUDE.md` менять, только если фича вводит новое общее правило.

## 10. Ревью
- Запусти субагента `code-reviewer` (`.claude/agents/code-reviewer.md`) на изменения фичи, как команда `/review`.
- Находки Critical и High исправь, остальные перечисли пользователю. Если субагент недоступен, скажи, что независимого ревью не было.

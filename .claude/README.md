# .claude

Агентная методология lobby_discord_bot: субагенты, команды и skills, с которыми
Claude Code работает в этом репозитории. Здесь описано, *как* работать с кодом,
а не ход конкретной задачи.

Правила проекта живут в `CLAUDE.md`. Агенты, команды и skills их применяют, но
не дублируют и не ослабляют: если правило нужно поменять, его меняют в
`CLAUDE.md`, а не здесь.

## Структура

- `agents/` - субагенты (Markdown с frontmatter).
- `commands/` - slash-команды (`/имя` = `commands/имя.md`). Команда это тонкая
  обёртка: она передаёт аргументы субагенту или skill-владельцу, сама логику не
  содержит.
- `skills/` - skills проекта (`skills/<имя>/SKILL.md`). Одна процедура живёт в
  одном skill, команды на него ссылаются.

| Что | Файл | Как вызвать |
|---|---|---|
| Ревьюер кода | `agents/code-reviewer.md` | `/review [объём]` или «запусти code-reviewer» |
| Новая фича | `skills/lobby-bot-new-feature/SKILL.md` | `/new-feature <описание>` или по смыслу задачи |

## Соглашения

- Один файл на одну задачу, имена в kebab-case. Имя в frontmatter совпадает с
  именем файла (агент) или папки (skill).
- Значения frontmatter, в которых есть `: `, в двойных кавычках, иначе YAML не
  разберётся.
- `settings.local.json` личный (разрешения Claude Code), он в `.gitignore`.
- Секретов, значений из `.env` и данных игроков здесь нет и быть не должно.
- Ход задач, планы и заметки по конкретной работе сюда не кладутся: они остаются
  в разговоре. Устойчивые правила и выводы переносятся в `CLAUDE.md`.
- Агенты, команды и skills не дают права коммитить или пушить: коммит в `main`
  сразу выкатывается в прод, это делается только по просьбе пользователя.

## Проверка

`tests/test_agent_methodology.py` (входит в обычный `pytest`) проверяет
frontmatter, совпадение имён и что упомянутые в файлах пути внутри `.claude`
существуют.
